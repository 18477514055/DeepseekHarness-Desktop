fix(ci): 放宽 CI 上的冒烟超时，并补上失败诊断

## 背景

上一步 CI 的合规 job 与许可校验均已通过，只剩最后的冒烟测试失败。
从步骤耗时看出根因：该步骤跑满 **72 秒**才退出，而 runSmoke() 内部的
超时定时器是 **60 秒** => 它走的是 timeout 分支（退出码 2），
即官方前端没能在 60 秒内完成加载。

原因：CI 的 windows-latest runner 是**无 GPU 的虚拟机**，
冷启动官方 dsh 服务器 + 加载官方前端远慢于真机。
这是上游遗留的环境适配问题，与合规改造无关。

## 修复

1. src/main.js：把冒烟超时上限改为可由 `DSH_SMOKE_TIMEOUT_MS` 环境变量覆盖。
   - **不设该变量时行为与上游完全一致（仍是 60000）**，真机不受影响；
   - 非法值安全回退到 60000（已实测：空值/垃圾值 -> 60000，150000 -> 150000）。
2. ci.yml：冒烟步骤设 `DSH_SMOKE_TIMEOUT_MS=150000`。
3. ci.yml：新增 `if: failure()` 的诊断步骤，失败时打印
   smoke-result.json、server.log 尾部、shell.log 尾部。
   原先失败只有一句 "exit code 2"，看不出是服务器没起来还是前端没注入
   __DSH_BOOT__，这次补上以便后续定位。
4. .gitignore：忽略 _msg.txt 类提交信息草稿（本仓库沿用不提交草稿的做法）。

## 说明

这是本次改造中**唯一一次触碰 src/ 运行时代码**，且改动被刻意设计为
默认路径零行为变化（仅新增一个可选环境变量）。
